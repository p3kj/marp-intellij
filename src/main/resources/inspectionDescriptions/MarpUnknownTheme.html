Reports a theme directive of a Marp deck that names a theme which is neither built into Marp (default, gaia, uncover) nor one of your custom themes. Marp ignores it and keeps the previous theme (or the default one); only the preview shows a warning. 
---
marp: true
theme: sketch
---

The same check applies to theme in a directive comment. Theme names are case-sensitive.

Quick fixes (Alt+Enter):

  • Add a theme CSS file or folder to Settings | Tools | Marp.
  • Create a .marprc.yml with a themeSet, or open the one that the project already has. Only offered while "Also use themeSet from .marprc.yml" is on.
  • Open Settings | Tools | Marp.

The name of a theme is the /* @theme name */ comment at the top of its CSS file.

The inspection stays quiet when it cannot be sure that the theme is missing: while the themes are still loading, in an untrusted project (custom themes are not loaded there), and while any theme source has a problem, such as a missing file, a failed download or a broken .marprc. The preview names those problems.
